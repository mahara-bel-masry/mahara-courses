# ورقة مرجع دوكر كومبوز - درس DE5.6

## المفاهيم
| المفهوم | معناه |
| --- | --- |
| compose.yaml | ملف نصي واحد يوصف المنظومة كلها، يتراجع في جيت زي أي كود |
| services | أهم كلمة في الملف: كل سيرفس تعريف كونتينر هيشتغل |
| healthcheck | فحص دوري (هنا `redis-cli PING`) يثبت إن السيرفس جاهز فعلًا، مش مجرد اتشغل |
| depends_on + condition | ترتيب تشغيل حقيقي: `service_healthy` يستنى الفحص، ومفيش اعتماد من غيره بيبقى ترتيب بدء بس |
| شبكة المشروع | كومبوز بيعمل شبكة خاصة، والخدمات بتشوف بعض بالاسم مش بالآي بي |
| named volume | مخزن خارجي ليه اسم ثابت بيديره دوكر، بيفضل عايش بعد مسح الكونتينرات وإعادة التشغيل، وده مش ضمانة ضد كل سيناريو فقدان |
| anonymous volume | لو الإيميج معلن VOLUME (زي ريدس /data) من غير named volume، دوكر بيعمل فوليوم من غير اسم بيفضل مع الكونتينر، وبعد down وup جديدة بيتعمل واحد تاني فاضي والقديم بيتساب (يرجع يدوي بس بصعوبة)، فسمّي الفوليوم دايمًا |

## أوامر كومبوز
| الأمر | بيعمل إيه |
| --- | --- |
| `docker compose up -d --build` | يبني اللي محتاج بناء ويشغل المنظومة كلها في الخلفية بترتيب الاعتماد |
| `docker compose ps` | السيرفسات الشغالة بس، والواقف أو المخلص مخفي افتراضي |
| `docker compose ps -a` | يعرض الواقف والمخلص كمان |
| `docker compose logs app` | لوجات سيرفس معين |
| `docker compose exec db redis-cli PING` | تنفيذ أمر جوه سيرفس شغال |
| `docker compose down` | يمسح الكونتينرات والشبكة، والفوليومز بتفضل |
| `docker compose down -v` | يمسح كمان الفوليومز المعرفة في الملف: عملية مدمرة للبيانات |

## شروط depends_on
| الشرط | معناه |
| --- | --- |
| `service_started` | الافتراضي: الكونتينر اتشغل وخلاص |
| `service_healthy` | يستنى فحص الصحة يعدي (اختيارنا في الدرس) |
| `service_completed_successfully` | يستنى مهمة بتخلص بنجاح، زي سيرفس تهيئة بيعمل مرة واحدة |

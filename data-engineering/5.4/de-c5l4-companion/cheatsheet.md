# ورقة مرجع: جيت هاب والريموت

## الفكرة في سطر

جيت أداة على جهازك، وجيت هاب استضافة لمخازن جيت بواجهة ومجتمع. الريموت اسم بيشاور على مخزن تاني، وأوريجن هو الاسم المتعارف عليه للأساسي. مخازن السيرفرات بتكون bare: تاريخ ولقطات من غير مجلد شغل.

## الربط والرفع الأول

- `git init --bare <مسار>` إنشاء مخزن سيرفر (في التدريب محلي، وعلى جيت هاب بيتعمل لك من الموقع)
- `git remote add origin <رابط أو مسار>` ربط المخزن المحلي بالريموت
- `git remote -v` عرض رابطي السحب fetch والرفع push
- `git push -u origin main` أول رفع للتاريخ كله مع ربط التتبع
- `git branch -vv` عرض الفروع وعلامة الربط `[origin/main]`
- `git remote show origin` تقرير كامل: الروابط والفرع الافتراضي والمتتبع
- الفرع الافتراضي إعداد قابل للتغيير: `git symbolic-ref HEAD refs/heads/main` على مخزن bare، ومن إعدادات الريبو على جيت هاب
- الرفع على جيت هاب محتاج مصادقة: توكن شخصي مع HTTPS، أو مفتاح SSH، أو مدير كريدنشالز (مش بنعرض أي كريدنشالز في الدرس)

## النسخة التانية

- `git clone <رابط> <مجلد>` نسخة كاملة بالتاريخ كله بنفس الهاشات (ده الكلون العادي؛ الكلون الضحل `--depth` بياخد عمق محدد بس)
- الكلون بيربط التتبع تلقائيًا، فـ `git push` و`git pull` يشتغلوا من غير تحديد
- الملفات غير المتتبعة المستبعدة بملف `.gitignore` مش بتسافر للريموت ولا بتتكلون (الاستبعاد بيمنع التتبع الجديد بس: ملف اتتبع قبل كده بيفضل متتبع وبيسافر، وسر اتسجل في كوميت قديم الاستبعاد ميمسحوش). البيانات والأسرار مكانها مش في جيت
- بعد الكلون على جهاز جديد: `git config user.name` و`git config user.email` محليًا على النسخة

## الحلقة اليومية

- `git push` رفع الكوميتات الجديدة للريموت المتربط
- `git fetch` جلب الأخبار من الريموت من غير ما يلمس شغلك (بيحدث مؤشرات origin بس)
- `git status` بعد الفيتش يقولك فرعك متأخر قد إيه
- `git log main..origin/main` عرض الكوميتات الجاية من الريموت قبل ما تاخدها
- `git pull` بالإعداد الافتراضي = fetch ثم merge في أمر واحد. ولو فعلت `pull.rebase` أو `pull.ff only` بيتصرف بالسياسة المفعلة

## الـ pull request (محاكاة محلية لفلو جيت هاب)

- من المطور: `git switch -c feature/<اسم>` ثم شغل وكوميت ثم `git push -u origin feature/<اسم>`
- من المينتينر: `git fetch` ثم مراجعة بـ `git diff main..origin/feature/<اسم>`
- الدمج: `git merge --no-ff origin/feature/<اسم> -m "merge: <وصف> (reviewed)"` — كوميت دمج ليه أبوين عشان التاريخ يحتفظ بشكل فرع المراجعة. على جيت هاب ده خيار create a merge commit في زرار الدمج، وفيه كمان squash وrebase بسلوك مختلف
- ثم `git push`، والمطور يعمل `git pull` ويمسح فرعه بـ `git branch -d feature/<اسم>` (جيت بيوافق لأنه اتدمج فعلًا)

## الريدمي

- التشريح: اسم وسطر تعريف، ليه موجود، المتطلبات، أمر التشغيل، مثال حقيقي من الناتج، هيكل الملفات، خطة التطوير
- ماركداون: `#` للعناوين، `-` للقوائم، تلات تيلدا `~~~` أو باكتيك حوالين بلوكات الكود
- اكتبه لحد عمره ما شافك: لو شغل مشروعك من غير ما يسألك، إنت كسبت

## التاجات والإصدارات

- `git tag -a v1.0 -m "<رسالة>"` تاج مشروح (annotated): معاه رسالة وتاجر وتاريخ. التوقيع الرقمي حاجة تانية ومحتاج `-s` ومفتاح توقيع
- `git tag -l` عرض التاجات
- `git push origin v1.0` رفع التاج (مش بيسافر مع الpush العادي)
- `git push --tags` رفع كل التاجات
- `git show v1.0 --stat` تفاصيل التاج والكوميت اللي عليه
- صفحة releases على جيت هاب بتتبني على التاجات: إصدار رسمي بملاحظات ومرفقات
